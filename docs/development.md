# Development

Prerequisites: Rust stable (pinned via `rust-toolchain.toml`) and
[`just`](https://github.com/casey/just).

```shell
just bootstrap          # install cargo-nextest, cargo-dist, cargo-binstall
just fmt                # format
just lint               # clippy -D warnings
just test               # nextest workspace
just build              # cargo build --workspace
just install            # cargo install --path mmk-cli --locked
just release-plan       # show what the release pipeline would produce
just release-build-host # smoke-build the host-platform tarball locally
```

## Workspace layout

```
mmk-core/    metric engine — pure functions over Vec<Commit>, no I/O
mmk-git/     Git history walker built on gix
mmk-config/  Config + mokumokuren.toml loader
mmk-cli/     The mokumokuren / mmk binary (lib + two bins)
docs/        Schema reference, metrics reference, this file
```

## Test discipline

Write the failing test before the implementation, at the level that
actually exercises the failure mode. Smoke-checks that pass on
broken code aren't tests; oracle-level checks (compare against
`git diff --numstat`, against hand-computed values, against an
external tool) are the ones that catch silent miscounts. The
integration tests live in `mmk-cli/tests/`; pure-metric tests in
`mmk-core/tests/`.

Two files codify the contract a future maintainer is most likely to
break:

- `mmk-cli/tests/schema.rs` — locks the JSON shape against
  `docs/schema.md`. Renaming any documented field without updating
  both the docs and this test fails the build.
- `mmk-cli/tests/readme_examples.rs` — every fenced ```shell block in
  `README.md` is parsed and run against the canonical fixture. A
  README example that no longer works fails the test before the
  release.

## Benchmarks

```shell
cargo bench -p mmk-core --bench coupling   # coupling stage
cargo bench -p mmk-core --bench metrics    # weighted_churn stage
```

The coupling bench guards a perf budget on a synthetic 2k-commit
fixture. Real-repo perf testing is run separately and is not part of
the workspace bench harness today.

## Performance

See [`docs/performance.md`](./performance.md) before optimising
anything. It captures where the time actually goes, the
`MMK_TRACE` / `dhat-heap` / samply tooling, the
`/tmp/mmk-fixtures` regression-fixture workflow, prior experiments
that didn't pay off (so they're not redone), and the open
architectural questions for the next pass.

## Release

The release pipeline is generated by `cargo-dist` and lives at
`.github/workflows/release.yml`. Tag a version, push the tag, and the
pipeline produces installer scripts plus prebuilt tarballs.
